# 报告与格式交付

## 默认成稿结构

这是本用户确认的 OiiOii 案例式交付偏好；用户指定其他结构时以其要求为准。参考案例用于组织章节、分析深度和视觉表达，正文只讲当前产品，不添加“与案例结构对照”、逐节对比或方法执行记录。

- **（一）拆解产品的思路**：简短交代分析切入点和任务，不展开研究台账。
- **（二）产品介绍**：一句话定位、产品形态、核心构成和典型场景。先用普通用户能理解的语言解释产品，再讲实现。
- **（三）效果体验：用一个场景测试它的能力**：任务、主要步骤、截图、产物及定性评价；没有完成生成或导出时用一句自然语言说明范围，不虚构实测或评分。
- **（四）产品定位**：目标用户、使用/买单/验收角色、差异化价值。
- **（五）产品拆解**：1. 市场层（需求与竞争）；2. 商业层（获客、收费、护城河）；3. 场景/用户层（功能模块、正向路径和修改/异常路径）；4. 技术层（整体职责、全局上下文、适用的 Agent 或逻辑模块、工具及技术问题）；5. 模型层（分类型号、任务映射、选择与成本）；6. 问题与改进。基础资产与方法可放入商业护城河、技术上下文及总览图，避免重复成章。
- **（六）整体框架**：四层分组总览图片与简短说明，收束全篇。

用户认可内容、只要求调整章节或图示时，保留实质分析，不重新扩写整篇。技术深拆只拆确有依据的 Agent 或功能职责，不为了模仿案例而虚构多 Agent 数量。

## 表格、截图与图示

分析正文结合图表展开，不写成连续长文。图表服务理解，不以数量为目标：

- 型号较多时提供分类表，分别列生图、生视频、文本/规划、音频等适用类别；包含已观察型号、使用步骤、选择要点和相关规格/报价。保留具体型号而非只写系列名，不把候选项当成质量排名，不为填表补造未知参数或供应商。
- 将功能模块、用户角色、人机分工、模型任务映射、计费和改进建议等并行信息用表格表达，避免表格与正文逐字重复。
- 关键操作步骤放真实截图并配分析；截图不等于最终效果证明。用户流程图表现正向路径以及局部修改/异常回路；技术图表现模块关系、共享上下文和资产复用。
- 指定参考图时直接查看用户所指的图；“整体框架图”不能拿 Agent 构成图代替。参考无法识别时先定位，避免依据名称猜布局。

### 整体框架图

绘制时读取 [图形模板与替换规则](diagram-template.md)，使用其中链接的可编辑 SVG 底稿。

本用户默认偏好 OiiOii 最终框架的四层布局：左侧层名，右侧分组容器，容器内排列功能卡片。用户层用浅蓝，应用层用浅黄，模型层用浅紫，基础层用灰蓝，保持浅色背景、统一细边框与清晰字号。

- **用户层**：核心创作入口、项目管理和资产入口等。
- **应用层**：导演/编排职责、制作模块，以及旁侧工具与控制组。明确逻辑模块不等于独立 Agent。
- **模型层**：按图片、文本/规划、音频、视频分组，列出有依据的模型。未知处用简短自然语言说明，不加证据状态标签。
- **基础层**：项目数据、资产、工作流、创作方法或知识内容，只放有依据的对象；不能照搬案例里的 RAG、训练数据或知识库。

总览图强调分组，不强行加入交叉连线。具体流程图则优先从左到右，按入口、规划编辑、执行交付等职责分区，用少量主路径和独立的复用/反馈通道表达关系；避免拥挤纵向链和穿过文字的连线。

### 图片交付与检查

重要框架、架构和流程图默认交付实际可显示的图片，不能只留下 Mermaid 源码。技术框图优先用可编辑 SVG 等确定性绘图生成，并导出 PNG 嵌入 Markdown；源文件随包保留，便于修改。用户重画某一节时，替换对应图片和正文引用，并同步更新打包文件。

逐张查看渲染结果，检查中文字形、字号、对齐、间距、线条交叉、遮挡和裁切。正文用相对路径引用图片；交付检查所有引用存在。打包报告与实际引用图片，可附图的可编辑源文件；内部研究目录不默认打包。

## 内部研究与成稿边界

核实状态、证据编号、事实/推断标签、验证台账和待核实清单只留在内部研究记录，默认不放正文、表格、图或附录。保留必要来源链接和简短体验范围；用自然措辞区分事实与设计推导。证据充分才评分，其余给定性结论，未知信息不能为完整而补入。

## 格式选择

指定格式直接执行；未指定默认本地 Markdown。风格待定不阻塞内容。默认采用易读标题、表格、图片与图例，不自行建立品牌体系。

### Markdown

UTF-8 `.md`，图片放报告旁资源目录，正文用相对路径便于整体移动。重要图示使用可直接显示的图片；Mermaid 可作为可编辑辅助，不作为唯一图示交付。核对图片、表格和来源链接；聊天交付给绝对路径链接。

### HTML

生成实际可打开的静态 `.html`，不自动公开部署。包含导航、语义化标题、响应式表格、截图说明与打印样式；沿用成稿不展示内部证据状态的规则。

默认不依赖 CDN、远程脚本或字体；图用内嵌 SVG 或其他离线方式。单文件交付时内嵌必要图片，否则连资源目录打包。用可用浏览器核验正文、图、表、图片及窄屏显示；无法视觉核验时说明限制。

### 飞书文档

优先用可用文档工具/连接会话；没有工具时可用浏览器正常创建和填写。选择输出飞书文档可授权创建该报告；目标空间/文档缺失且影响创建时，仅询问该缺失信息。向现有文档写入时保留无关内容。

写入正文、表格、图片和必要来源链接，工具不支持时用替代呈现并说明限制。不只贴 Markdown 源码就声称完成排版。写入后复读核验，交付真实可访问链接；空文档不算完成。

缺连接、登录或写入能力时，先保存完整本地 Markdown 和资源，明确飞书交付尚未完成及需要的连接/接管。不得伪造链接、擅自公开分享或向他人发送文档。

## 交付核验

正文、图表与内部研究一致，评分有充分依据；说明体验范围和日期，图片可读并脱敏。最终简要说明文件/文档位置、验证情况与重要未决项。未完成的实测或在线写入不能称为成功。
